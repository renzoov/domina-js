## Lo que te llevas

Cada framework tiene su forma de escribir, pero por debajo todos usan lo que ya viste: **eventos** para reaccionar, el **DOM** para mostrar, **promesas** y `async`/`await` para esperar datos, **módulos** para ordenar el código y **closures** por todas partes. Cuando algo de un framework te parezca magia, casi siempre es una de estas piezas bien combinada.

Por eso este es el mejor momento para elegir: con los fundamentos firmes, aprender un framework nuevo lleva semanas, no meses.

## El problema que resuelven

Mira este contador escrito solo con JavaScript:

```js
document.body.innerHTML = `<button id="mas">Sumar</button> <p id="cuenta"></p>`;
let cuenta = 0;
const parrafo = document.querySelector("#cuenta");

function mostrar() {
  parrafo.textContent = `Clics: ${cuenta}`;
}

document.querySelector("#mas").addEventListener("click", () => {
  cuenta++;
  mostrar();   // ← hay que acordarse de actualizar la página cada vez
});

mostrar();
document.querySelector("#mas").click();
console.log(parrafo.textContent);
```

Funciona, y para algo chico es lo correcto. El problema aparece cuando la aplicación crece: decenas de datos que cambian, cada uno mostrado en varios lugares, y en cada cambio hay que acordarse de actualizar **todos**. Cuando uno se olvida, aparece un error.

Los frameworks de interfaz invierten la idea: tú describes **cómo se ve la página para cada estado**, y el framework se ocupa de actualizar el DOM cuando el estado cambia. En las próximas lecciones vas a ver este mismo contador escrito con cada uno.

## Librería, framework y meta-framework

- Una **librería** es código que **tú llamas** cuando lo necesitas: React, por ejemplo, solo se ocupa de los componentes.
- Un **framework** es al revés: **él llama a tu código** y decide la estructura de la aplicación. Angular trae las rutas, los formularios y la forma de organizar todo.
- Un **meta-framework** se arma sobre una librería de interfaz y agrega lo que una aplicación completa necesita: rutas según los archivos, renderizado en el servidor, carga de datos y una parte de backend. Next.js lo hace para React, Nuxt para Vue y SvelteKit para Svelte.

En la práctica, todos dicen "framework" para casi todo. Lo importante es saber cuánto decide la herramienta por ti.

## Cómo elegir

Algunas preguntas que ayudan:

- **¿Qué piden los trabajos que te interesan?** React es el más pedido en casi todo el mundo; Angular es muy común en empresas grandes; Vue tiene mucha presencia en algunos países y comunidades.
- **¿Qué vas a construir?** Para un sitio con mucho contenido (un blog, una documentación), Astro. Para una aplicación muy interactiva, React, Vue, Svelte o Solid. Para una API, uno de backend.
- **¿Cuánto quieres que se decida por ti?** Angular y NestJS deciden casi todo; React y Express te dejan elegir cada pieza.

Y una regla para no perder el rumbo: el ecosistema cambia rápido, pero los fundamentos no. Lo que aprendiste en este curso te va a servir con cualquiera de ellos, y con los que todavía no existen.

## Resumen

- Todos los frameworks están hechos de eventos, DOM, promesas, módulos y closures.
- Resuelven un problema concreto: mantener la página al día cuando el estado cambia.
- Librería (tú la llamas), framework (te llama a ti) y meta-framework (la aplicación completa alrededor de una librería).
- Elige uno de interfaz, llévalo hasta un proyecto real, y después suma los demás.
