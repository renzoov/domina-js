## La idea

Un decorator es una **función** que se aplica a una clase o a uno de sus miembros con `@nombre`. Recibe lo que decora y puede devolver un reemplazo:

```js
class Pedido {
  @registrar
  confirmar(id) {
    return `pedido ${id} confirmado`;
  }
}
```

Es una forma declarativa de escribir algo que ya sabes hacer: **envolver** una función con otra, como en *Funciones como valores*. Sin la sintaxis nueva, sería:

```js
function registrar(metodo) {
  return function (...args) {
    console.log(`llamando con ${args.join(", ")}`);
    return metodo.apply(this, args);
  };
}

class Pedido {
  confirmar(id) {
    return `pedido ${id} confirmado`;
  }
}

Pedido.prototype.confirmar = registrar(Pedido.prototype.confirmar);
console.log(new Pedido().confirmar(7));
```

## Cómo se escribe uno

En la propuesta actual, un decorator recibe dos argumentos: el **valor** decorado (el método, la clase, el campo…) y un objeto **contexto** con información sobre él:

```js
function soloLectura(valor, contexto) {
  // contexto.kind: "method", "field", "class", "getter", "setter", "accessor"
  // contexto.name: el nombre del miembro
  if (contexto.kind === "field") {
    return function (inicial) {
      return Object.freeze(inicial);
    };
  }
}

class Ajustes {
  @soloLectura
  colores = { fondo: "negro" };
}
```

Para un método, devolver una función la reemplaza; para un campo, devolver una función transforma su valor inicial. Si no devuelve nada, el miembro queda como estaba.

La propuesta también agrega `accessor`, una palabra clave para crear un getter y un setter automáticos que los decorators pueden interceptar:

```js
class Formulario {
  @validarEmail
  accessor email = "";
}
```

## Dos versiones: la antigua y la de la propuesta

Los frameworks que usan decorators desde hace años (Angular, NestJS, TypeORM) nacieron con una **versión antigua**, que TypeScript activa con `experimentalDecorators: true`. Tiene otra firma: recibe el prototipo, el nombre y un descriptor de la propiedad.

Desde TypeScript 5.0, sin esa opción, se usan los decorators de la **propuesta actual**, los de esta lección. Si empiezas un proyecto nuevo, usa estos. Si trabajas con un framework que pide la versión antigua, sigue su documentación.

<Nota tipo="ojo">
  Que TypeScript los acepte no significa que JavaScript los tenga: TypeScript los **transforma** en código normal al compilar. Hasta que la propuesta llegue a Stage 4 y los navegadores la implementen, la `@` en un archivo `.js` es un `SyntaxError`.
</Nota>

## Resumen

- Un **decorator** es una función aplicada con `@nombre` a una clase o a sus miembros.
- Recibe el **valor** decorado y un **contexto** (`kind`, `name`…), y puede devolver un reemplazo.
- Está en **Stage 2.7**: hoy se usa con TypeScript o Babel.
- `experimentalDecorators` de TypeScript es la versión **antigua**; la de la propuesta es la recomendada para proyectos nuevos.
- Sin herramientas, consigues lo mismo envolviendo el método con una **función de orden superior**.
