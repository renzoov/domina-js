## ESLint

```bash
npm init @eslint/config@latest      # asistente que crea la configuración
npx eslint .                        # revisa el proyecto
npx eslint . --fix                  # corrige lo que se puede corregir solo
```

La configuración es un archivo `eslint.config.js` (la *flat config*) que exporta un array de objetos. Cada objeto se aplica en orden, y los de después pueden cambiar a los de antes:

```js
// eslint.config.js
import js from "@eslint/js";
import globals from "globals";
import { defineConfig } from "eslint/config";

export default defineConfig([
  js.configs.recommended,                      // las reglas recomendadas
  {
    files: ["src/**/*.js"],
    languageOptions: { globals: globals.browser },   // variables del navegador
    rules: {
      "no-unused-vars": "warn",                // aviso en lugar de error
      eqeqeq: "error",                         // obliga a usar === y !==
    },
  },
  { ignores: ["dist/"] },
]);
```

Cada regla puede estar en `"off"`, `"warn"` o `"error"`. Las reglas recomendadas atrapan errores de verdad: variables sin declarar, código inalcanzable, condiciones que siempre dan lo mismo, claves repetidas en un objeto. Para TypeScript está **typescript-eslint**, y cada framework tiene su plugin.

## Prettier

Prettier no busca errores: **reescribe** el código con un estilo fijo (sangría, comillas, punto y coma, largo de las líneas). Tiene muy pocas opciones a propósito: la idea es dejar de discutir el estilo.

```bash
npm install -D prettier
npx prettier . --write              # formatea todo
npx prettier . --check              # solo comprueba (para integración continua)
```

```json
// .prettierrc
{ "printWidth": 100, "singleQuote": false }
```

Si usas los dos, desactiva en ESLint las reglas de estilo (lo hace `eslint-config-prettier`): cada herramienta a lo suyo.

## Biome

**Biome** es un linter y formateador en un solo programa, escrito en Rust y mucho más rápido. Una configuración, un comando:

```bash
npm install -D @biomejs/biome
npx biome init
npx biome check --write .           # lint + formato, y corrige lo que puede
```

Tiene la mayoría de las reglas de ESLint y es compatible con el estilo de Prettier. Es una buena opción para proyectos nuevos; ESLint sigue siendo el estándar por su enorme cantidad de plugins.

## Dónde ejecutarlos

- **En el editor**: con la extensión de ESLint (o de Biome) ves los errores mientras escribes, y con "formatear al guardar" no piensas más en el estilo.
- **Antes de cada commit**: herramientas como **lint-staged** con **husky** o **lefthook** revisan solo los archivos que cambiaron.
- **En la integración continua**: `eslint .` y `prettier --check .` en cada pull request, para que nada se cuele.

<Nota tipo="consejo">
  Agrega los scripts al `package.json` (`"lint": "eslint ."`, `"format": "prettier . --write"`): así cualquiera que llegue al proyecto sabe cómo ejecutarlos, sin leer documentación.
</Nota>

## Resumen

- Un **linter** (ESLint) encuentra errores y malas prácticas sin ejecutar el código.
- Un **formateador** (Prettier) unifica el estilo; no discutas más de comillas.
- ESLint usa la *flat config*: un array de objetos en `eslint.config.js`.
- **Biome** hace las dos cosas, muy rápido.
- Ejecútalos en el editor, antes de cada commit y en la integración continua.
