## extends

`class Hija extends Padre` crea una clase que hereda todos los métodos de `Padre`:

```js
class Usuario {
  constructor(nombre) {
    this.nombre = nombre;
  }
  saludar() {
    return `Hola, soy ${this.nombre}`;
  }
}

class Admin extends Usuario {
  borrar(cosa) {
    return `${this.nombre} borró ${cosa}`;
  }
}

const eva = new Admin("Eva");
console.log(eva.saludar());   // heredado
console.log(eva.borrar("un comentario"));
```

`Admin` no tiene constructor, así que usa automáticamente el de `Usuario`.

## super() en el constructor

Si la hija tiene constructor propio, **tiene que** llamar a `super(...)`, el constructor del padre, **antes** de usar `this`. El objeto lo crea el padre: hasta entonces, `this` no existe.

```js
class Usuario {
  constructor(nombre) {
    this.nombre = nombre;
  }
}

class Admin extends Usuario {
  constructor(nombre, nivel) {
    super(nombre);        // primero el padre
    this.nivel = nivel;   // después lo propio
  }
}

console.log(new Admin("Eva", 3));
```

## Sobrescribir y extender métodos

Si la hija define un método con el mismo nombre, **tapa** al del padre (lo sobrescribe). Con `super.metodo()` puede llamar a la versión del padre y **extenderla**:

```js
class Notificacion {
  texto() {
    return "Tienes un mensaje";
  }
}

class Urgente extends Notificacion {
  texto() {
    return `⚠ ${super.texto().toUpperCase()}`;
  }
}

console.log(new Notificacion().texto());
console.log(new Urgente().texto());
```

## La cadena por debajo

`extends` arma la cadena de prototipos que ya conoces:

```
admin  →  Admin.prototype  →  Usuario.prototype  →  Object.prototype  →  null
```

Por eso funciona `instanceof`: recorre la cadena buscando el `prototype` de la clase.

```js
class Figura {}
class Circulo extends Figura {}

const c = new Circulo();
console.log(c instanceof Circulo, c instanceof Figura, c instanceof Object);
console.log(Object.getPrototypeOf(Circulo.prototype) === Figura.prototype);
```

## Extender clases nativas

Puedes extender `Error`, `Array`, `Map` y otras clases del lenguaje. El caso más útil son los **errores propios**, que llevan datos extra y se distinguen con `instanceof`:

```js
class ErrorHttp extends Error {
  constructor(estado, mensaje) {
    super(mensaje);
    this.name = "ErrorHttp";
    this.estado = estado;
  }
}

try {
  throw new ErrorHttp(404, "No encontrado");
} catch (error) {
  if (error instanceof ErrorHttp) {
    console.log(error.estado, error.message);
  }
}
```

<Nota tipo="consejo">
  La herencia une mucho a las dos clases: un cambio en el padre afecta a todas las hijas. Úsala cuando la hija **es** de verdad un tipo del padre. Para el resto, el próximo tema: *Composición frente a herencia*.
</Nota>

## Resumen

- `class Hija extends Padre` hereda los métodos del padre.
- En un constructor hijo, `super(...)` va **antes** de usar `this`.
- Un método con el mismo nombre **sobrescribe**; `super.metodo()` llama al del padre.
- `extends` enlaza los prototipos; `instanceof` recorre esa cadena.
- Extender `Error` es la forma de crear errores propios con datos extra.
