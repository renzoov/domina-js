## De dónde salen

Ya sabes dos cosas:

1. Una función ve las variables del scope donde **fue escrita** (scope léxico).
2. Cuando una función termina, su scope normalmente desaparece.

Un closure aparece cuando las dos chocan: una función interna **sale** de la función que la creó (porque se devuelve, se guarda o se pasa a otra función) y sigue necesitando sus variables. El motor no las borra: la función interna **se las lleva**.

```js
function crearSaludo() {
  const mensaje = "¡Hola!";
  return function () {
    console.log(mensaje);
  };
}

const saludar = crearSaludo();  // crearSaludo ya terminó…
saludar();                       // …pero saludar todavía recuerda mensaje
```

## Cada llamada, un entorno nuevo

Como viste con los contadores del pizarrón, **cada** ejecución de la función externa crea variables nuevas, y cada función devuelta recuerda las suyas:

```js
function crearContador() {
  let cuenta = 0;
  return () => ++cuenta;
}

const a = crearContador();
const b = crearContador();

console.log(a(), a(), a());  // 1 2 3
console.log(b());            // 1: b tiene su propia cuenta
```

## Para qué sirven

**Datos privados.** Las variables del entorno no se pueden tocar desde afuera: solo a través de las funciones que las recuerdan.

```js
function crearCuenta(saldoInicial) {
  let saldo = saldoInicial;
  return {
    depositar(monto) { saldo += monto; },
    consultar() { return saldo; },
  };
}

const cuenta = crearCuenta(100);
cuenta.depositar(50);
console.log(cuenta.consultar());  // 150
console.log(cuenta.saldo);        // undefined: no hay forma de llegar a saldo
```

**Fábricas de funciones.** Una función que fabrica otras ya configuradas, como `crearMultiplicador(2)`, que vas a escribir en el laboratorio.

**Callbacks.** Cada vez que pasas una función que usa variables de afuera (a un `setTimeout`, un `addEventListener`, un `map`…), esa función es un closure: recuerda esas variables para cuando la llamen, más tarde.

```js
function avisarEn(segundos, texto) {
  setTimeout(() => {
    console.log(`(${segundos} s después) ${texto}`);
  }, segundos * 1000);
}
```

## Closures en bucles

Con `let`, cada vuelta de un `for` tiene su propia variable, así que cada función creada en el bucle recuerda un valor distinto:

```js
const funciones = [];
for (let i = 0; i < 3; i++) {
  funciones.push(() => i);
}
console.log(funciones[0](), funciones[1](), funciones[2]());  // 0 1 2
```

Con `var` habría **una sola** `i` compartida por todas las vueltas, y las tres funciones devolverían 3. Era un error clásico antes de 2015, y otra razón para no usar `var`.

<Nota>
  Un closure mantiene vivas las variables que recuerda mientras la función exista. Si guardas sin querer un closure que recuerda un objeto enorme, ese objeto no se libera. Lo vas a ver en el tema *Memoria y recolector de basura*.
</Nota>

## Resumen

- Un **closure** es una función junto con las variables del entorno donde nació.
- La función puede seguir usando esas variables aunque la función que las creó ya haya terminado.
- **Cada llamada** a la función externa crea un entorno nuevo e independiente.
- Sirven para **datos privados**, **fábricas de funciones** y **callbacks** que recuerdan estado.
- Con `let`, cada vuelta de un bucle tiene su propia variable para los closures.
