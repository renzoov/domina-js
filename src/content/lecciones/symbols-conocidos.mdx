## Los que ya conoces

| Symbol | Lo usa… | Lo viste en |
|---|---|---|
| `Symbol.iterator` | `for...of`, spread, desestructuración | *El protocolo iterable* |
| `Symbol.asyncIterator` | `for await...of` | *Iteración asíncrona* |
| `Symbol.dispose` | `using` | *Gestión explícita de recursos* |
| `Symbol.asyncDispose` | `await using` | *Gestión explícita de recursos* |

Todos siguen la misma idea: el lenguaje define el **nombre** del gancho y tú pones la **función**.

## Symbol.toPrimitive

Cuando un objeto tiene que convertirse en un primitivo (en una suma, un template literal, una comparación), el lenguaje busca `[Symbol.toPrimitive](hint)`. El `hint` dice qué se espera:

- `"number"`: `+obj`, `obj * 2`, `obj > 3`
- `"string"`: `` `${obj}` ``, `String(obj)`
- `"default"`: `obj + algo`, `obj == algo`

```js
const duracion = {
  segundos: 90,
  [Symbol.toPrimitive](hint) {
    return hint === "string" ? `${Math.floor(this.segundos / 60)} min ${this.segundos % 60} s` : this.segundos;
  },
};

console.log(`Duró ${duracion}`);
console.log(duracion * 2);
console.log(duracion > 60);
```

Sin él, el lenguaje prueba con `valueOf()` y `toString()`, como viste en *Conversión de tipos*.

## Symbol.toStringTag

Cambia la etiqueta que muestra `Object.prototype.toString`, la forma más confiable de saber "qué es" un valor:

```js
class Billetera {
  get [Symbol.toStringTag]() {
    return "Billetera";
  }
}

console.log(Object.prototype.toString.call(new Billetera()));
console.log(Object.prototype.toString.call(new Map()));
console.log(Object.prototype.toString.call(null));
```

## Symbol.hasInstance

Decide qué responde `instanceof`. Permite que `instanceof` compruebe una **forma** en lugar de un prototipo:

```js
class Iterable {
  static [Symbol.hasInstance](valor) {
    return valor != null && typeof valor[Symbol.iterator] === "function";
  }
}

console.log([1, 2] instanceof Iterable);
console.log("hola" instanceof Iterable);
console.log({} instanceof Iterable);
```

## Otros

- **`Symbol.isConcatSpreadable`**: decide si `concat` reparte el objeto como un array.
- **`Symbol.species`**: el constructor que usan métodos como `map` para crear el resultado en clases que extienden `Array`.
- **`Symbol.match`, `replace`, `search`, `split`**: permiten que un objeto propio funcione como una expresión regular en los métodos de texto.
- **`Symbol.unscopables`**: un detalle histórico para el viejo `with`.

## El registro global: Symbol.for

`Symbol("x")` crea un symbol **nuevo** cada vez. `Symbol.for("x")` lo busca en un **registro global** y, si no existe, lo crea: dos partes del programa que no se conocen obtienen el mismo symbol.

```js
const a = Symbol("app.tema");
const b = Symbol("app.tema");
const c = Symbol.for("app.tema");
const d = Symbol.for("app.tema");

console.log(a === b, c === d);
console.log(Symbol.keyFor(c), Symbol.keyFor(a));
```

<Nota tipo="consejo">
  Usa nombres con prefijo en el registro global (`"mi-libreria.config"`), porque es compartido por todo el programa, incluidas las librerías. Y recuerda que los symbols conocidos (`Symbol.iterator` y compañía) no están en ese registro: son propiedades de `Symbol`.
</Nota>

## Resumen

- Los **symbols conocidos** son ganchos: el lenguaje busca esas claves en tus objetos.
- `Symbol.iterator`, `asyncIterator`, `dispose` y `asyncDispose` conectan con `for...of`, `for await` y `using`.
- `Symbol.toPrimitive` controla la conversión a número o texto según el `hint`.
- `Symbol.toStringTag` cambia la etiqueta de `Object.prototype.toString`; `Symbol.hasInstance`, el resultado de `instanceof`.
- `Symbol.for` comparte symbols a través de un registro global.
