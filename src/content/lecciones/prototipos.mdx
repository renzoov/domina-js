## El prototipo

Todo objeto tiene un enlace interno, que la especificación llama `[[Prototype]]`, a otro objeto: su **prototipo**. Puedes verlo con `Object.getPrototypeOf`:

```js
const vacio = {};
console.log(Object.getPrototypeOf(vacio) === Object.prototype);  // true
console.log(vacio.toString());  // [object Object]: heredado

const lista = [1, 2];
console.log(Object.getPrototypeOf(lista) === Array.prototype);   // true
```

## La cadena de prototipos

Cuando lees una propiedad, el motor:

1. La busca en el **propio** objeto.
2. Si no está, la busca en su **prototipo**.
3. Después, en el prototipo del prototipo, y así **hacia arriba**.
4. Si llega a `null` sin encontrarla, devuelve `undefined`.

Es la misma idea que la cadena de scopes del tema *Scope*, pero con objetos en lugar de variables. Un array, por ejemplo, tiene esta cadena:

```
lista  →  Array.prototype  →  Object.prototype  →  null
          (map, filter…)      (toString, hasOwnProperty…)
```

Por eso un array tiene a la vez `map` y `toString`: los dos están en su cadena.

## Object.create

`Object.create(proto)` crea un objeto vacío con el prototipo que elijas. Es la forma más directa de ver la herencia en acción:

```js
const vehiculo = {
  ruedas: 4,
  describir() {
    return `Tengo ${this.ruedas} ruedas`;
  },
};

const moto = Object.create(vehiculo);
moto.ruedas = 2;  // propia: tapa a la heredada

console.log(moto.describir());  // usa el método heredado con el dato propio
console.log(Object.hasOwn(moto, "ruedas"));     // true
console.log(Object.hasOwn(moto, "describir"));  // false: heredado
```

**Escribir** no sube por la cadena: `moto.ruedas = 2` crea una propiedad propia en `moto`, aunque `vehiculo` ya tenga `ruedas`. La propia tapa a la heredada, y `vehiculo` no cambia.

`Object.create(null)` crea un objeto **sin** prototipo: no hereda nada, ni siquiera `toString`. Se usa a veces como diccionario "limpio".

## Por qué importa

- **Los métodos se comparten.** Un método en el prototipo existe una sola vez, aunque haya un millón de objetos que lo usen.
- **`this` es quien llama.** El método vive en el prototipo, pero `this` es el objeto desde el que se lo llamó, así que trabaja con sus datos.
- **Así funcionan las clases.** `class` es una sintaxis más cómoda sobre este mismo mecanismo: los métodos van al prototipo y los datos, a cada instancia. Lo vas a ver en la próxima sección.

<Nota tipo="error">
  No modifiques los prototipos nativos (`Array.prototype.miMetodo = …`). Afecta a todos los objetos del programa, puede chocar con métodos que el lenguaje agregue en el futuro y rompe librerías. Pasó de verdad: por culpa de esto, un método de ES2019 tuvo que cambiar de nombre.
</Nota>

## Resumen

- Todo objeto tiene un **prototipo** (`Object.getPrototypeOf`), salvo los creados con `Object.create(null)`.
- Para leer una propiedad, el motor sube por la **cadena de prototipos** hasta encontrarla o llegar a `null`.
- Escribir crea siempre una propiedad **propia**, que tapa a la heredada.
- `Object.create(proto)` crea un objeto enlazado a `proto`.
- Los métodos de los nativos (`map`, `toString`…) viven en sus prototipos y se comparten.
- No modifiques los prototipos nativos.
