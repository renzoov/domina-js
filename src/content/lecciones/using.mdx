## El problema

```js
function abrir(nombre) {
  console.log("abre", nombre);
  return { cerrar: () => console.log("cierra", nombre) };
}

function procesar() {
  const archivo = abrir("datos.txt");
  try {
    console.log("procesando…");
    throw new Error("formato inválido");
  } finally {
    archivo.cerrar();   // hay que acordarse, en cada función
  }
}

try { procesar(); } catch (e) { console.log("error:", e.message); }
```

Funciona, pero con dos o tres recursos el código se llena de `try/finally` anidados, y basta un olvido para dejar algo abierto.

## using

Un objeto **desechable** (*disposable*) tiene un método bajo la clave `Symbol.dispose`. Si lo declaras con `using`, ese método se llama **automáticamente** al salir del bloque, pase lo que pase:

```js
function abrir(nombre) {
  console.log("abre", nombre);
  return {
    nombre,
    [Symbol.dispose]() {
      console.log("cierra", nombre);
    },
  };
}

function procesar() {
  using archivo = abrir("datos.txt");
  console.log("procesando", archivo.nombre);
  throw new Error("formato inválido");
}   // ← aquí se llama a archivo[Symbol.dispose](), aunque haya un error

try { procesar(); } catch (e) { console.log("error:", e.message); }
```

`using` declara una constante, como `const`, y solo se puede usar dentro de bloques, funciones y módulos.

## Varios recursos

Con varios `using`, se liberan en orden **inverso** al de apertura, como una pila: lo que se abrió después puede depender de lo anterior.

```js
const recurso = (n) => ({ [Symbol.dispose]: () => console.log("libera", n) });

{
  using conexion = recurso("conexión");
  using transaccion = recurso("transacción");
  console.log("trabajando");
}
```

Si el valor es `null` o `undefined`, `using` simplemente no hace nada al salir: útil para recursos opcionales.

## await using

Muchas limpiezas son **asíncronas**: cerrar una conexión, vaciar datos a disco. Para eso está `Symbol.asyncDispose`, con `await using`, que espera a que termine la limpieza:

```js
const esperar = (ms) => new Promise((r) => setTimeout(r, ms));

function conectar(nombre) {
  console.log("conecta", nombre);
  return {
    async [Symbol.asyncDispose]() {
      await esperar(20);
      console.log("desconectó", nombre, "(tardó 20 ms)");
    },
  };
}

async function tarea() {
  await using db = conectar("principal");
  console.log("consultando");
}

await tarea();
console.log("tarea terminada, conexión ya cerrada");
```

## DisposableStack

`DisposableStack` junta varias limpiezas en un solo objeto desechable. Sirve cuando no sabes de antemano cuántos recursos vas a abrir, o para recursos que no tienen `Symbol.dispose`:

```js
function prepararPantalla() {
  using pila = new DisposableStack();

  const intervalo = setInterval(() => {}, 1000);
  pila.defer(() => {
    clearInterval(intervalo);
    console.log("intervalo detenido");
  });

  const conexion = pila.use({ [Symbol.dispose]: () => console.log("conexión cerrada") });
  pila.adopt("suscripción", (s) => console.log(s, "cancelada"));

  console.log("pantalla lista");
  // Si algo fallara aquí, todo lo anterior se liberaría solo
  return pila.move();   // transfiere las limpiezas a quien llamó
}

{
  using limpieza = prepararPantalla();
  console.log("usando la pantalla");
}
```

- `defer(fn)` agrega una función de limpieza.
- `use(recurso)` agrega un objeto desechable y lo devuelve.
- `adopt(valor, fn)` agrega un valor cualquiera con su función de limpieza.
- `move()` pasa todo a una pila nueva, para que la función pueda devolver sus recursos sin liberarlos.

`AsyncDisposableStack` es la versión asíncrona, para `await using`.

<Nota>
  El lenguaje y las plataformas ya están adoptando el protocolo: en Node.js, los archivos de `fs/promises` y otros objetos tienen `Symbol.asyncDispose`, y los iteradores de los generadores tienen `Symbol.dispose`. Poco a poco, más APIs van a funcionar directamente con `using`.
</Nota>

## Resumen

- `using x = recurso` llama a `x[Symbol.dispose]()` al salir del bloque, también con errores, `return` o `break`.
- Los recursos se liberan en orden **inverso** al de apertura.
- `await using` y `Symbol.asyncDispose` para limpiezas asíncronas.
- `DisposableStack` (y `AsyncDisposableStack`) junta limpiezas con `defer`, `use`, `adopt` y `move`.
- Reemplaza los `try/finally` de limpieza, que eran fáciles de olvidar.
