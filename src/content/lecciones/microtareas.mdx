## Dos colas

| Cola | Qué va ahí |
|---|---|
| **Tareas** (macrotareas) | Callbacks de `setTimeout` y `setInterval`, eventos (clics, teclas), mensajes de workers, respuestas de red |
| **Microtareas** | Reacciones de promesas (`then`, `catch`, `finally`), lo que sigue a un `await`, `queueMicrotask(fn)` |

## El orden

Cada vuelta del event loop hace esto:

1. Ejecuta **una** tarea, la primera de la cola de tareas. (El programa principal cuenta como la primera.)
2. Vacía **toda** la cola de microtareas, incluidas las que se agreguen mientras tanto.
3. En el navegador, si toca, **dibuja** la página (y antes ejecuta los `requestAnimationFrame`).
4. Vuelve a empezar.

Como viste en el pizarrón, el resultado práctico es: **lo síncrono primero, después todas las microtareas, después una macrotarea**.

```js
console.log("1");
setTimeout(() => console.log("5: macrotarea"), 0);
queueMicrotask(() => console.log("3: microtarea"));
Promise.resolve().then(() => console.log("4: microtarea"));
console.log("2");
```

## await también es una microtarea

Lo que viene después de un `await` se retoma como microtarea:

```js
async function f() {
  console.log("B: f empieza");
  await null;
  console.log("D: f retoma (microtarea)");
}

console.log("A");
setTimeout(() => console.log("E: macrotarea"), 0);
f();
console.log("C");
```

## Microtareas que no terminan nunca

Como la cola de microtareas se vacía **entera** antes de seguir, una microtarea que siempre agenda otra impide que corra cualquier tarea: temporizadores, clics y el dibujo de la página.

```js
let vueltas = 0;
function sinFin() {
  vueltas++;
  if (vueltas < 100000) queueMicrotask(sinFin);  // con un límite, para no colgar esta página
}

setTimeout(() => console.log("el temporizador corrió después de", vueltas, "microtareas"), 0);
queueMicrotask(sinFin);
```

Sin el límite, el temporizador no correría nunca y la pestaña quedaría congelada. Con `setTimeout` en lugar de `queueMicrotask`, en cambio, cada vuelta le daría paso a los eventos y al dibujo.

## requestAnimationFrame

En el navegador, `requestAnimationFrame(fn)` ejecuta `fn` justo **antes del siguiente dibujo**, unas 60 veces por segundo (o al ritmo de la pantalla). Es el lugar correcto para animar:

```js
let x = 0;
function mover() {
  x += 2;
  if (x < 10) requestAnimationFrame(mover);
  else console.log("animación terminada en x =", x);
}
requestAnimationFrame(mover);
```

<Nota>
  ¿Para qué sirve `queueMicrotask` en la práctica? Para ejecutar algo "apenas termine el código actual", antes que cualquier evento o temporizador. Las librerías lo usan, por ejemplo, para agrupar varios cambios y procesarlos juntos una sola vez.
</Nota>

## Resumen

- Hay dos colas: **tareas** (temporizadores, eventos, red) y **microtareas** (promesas, `await`, `queueMicrotask`).
- Orden: lo síncrono, después **todas** las microtareas, después **una** tarea, y se repite.
- Por eso un `then` corre antes que un `setTimeout(…, 0)`.
- Microtareas que se encadenan sin fin congelan la página.
- `requestAnimationFrame` corre antes de cada dibujo: úsalo para animar.
