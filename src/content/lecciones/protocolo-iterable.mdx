## Dos piezas

El protocolo tiene dos partes, como muestra el pizarrón:

- Un **iterable** es un objeto que tiene un método bajo la clave `Symbol.iterator`. Ese método fabrica un iterador.
- Un **iterador** es un objeto con un método `next()`. Cada llamada devuelve `{ value, done }`: el siguiente valor, y si ya se terminó.

```js
const texto = "ok";
const it = texto[Symbol.iterator]();

console.log(it.next());
console.log(it.next());
console.log(it.next());
```

`Symbol.iterator` es uno de los **símbolos conocidos** que viste en *Symbols*: una clave especial que el lenguaje usa para pedirle algo a un objeto.

## Quién usa el protocolo

Todas estas herramientas piden un iterador y llaman a `next()` hasta ver `done: true`:

```js
const conjunto = new Set(["a", "b", "c"]);

for (const x of conjunto) console.log(x);    // for...of
console.log([...conjunto]);                  // spread
const [primero, segundo] = conjunto;         // desestructuración de arrays
console.log(primero, segundo);
console.log(Array.from(conjunto));           // Array.from
console.log(new Map([["k", 1]]).get("k"));   // el constructor de Map recibe un iterable
console.log(Math.max(...new Set([3, 9, 4]))); // spread en argumentos
```

Son iterables los arrays, los textos (por caracteres), `Map`, `Set`, los arrays tipados, `arguments` y los resultados de `entries()`, `keys()` y `values()`. Los objetos literales **no** lo son.

## Hacer iterable un objeto

Basta con darle un método `[Symbol.iterator]` que devuelva un iterador:

```js
const playlist = {
  canciones: ["Intro", "Tema 1", "Final"],
  [Symbol.iterator]() {
    let i = 0;
    const lista = this.canciones;
    return {
      next() {
        if (i < lista.length) {
          return { value: `♪ ${lista[i++]}`, done: false };
        }
        return { value: undefined, done: true };
      },
    };
  },
};

for (const c of playlist) console.log(c);
console.log([...playlist].length);
```

La posición (`i`) se crea **dentro** del método, así que cada recorrido empieza desde el principio.

<Nota tipo="ojo">
  Un **iterable** se puede recorrer muchas veces: cada vez fabrica un iterador nuevo. Un **iterador** es un recorrido de un solo uso: cuando llega a `done: true`, ya no da más valores. Esta diferencia va a importar mucho con los generadores.
</Nota>

## Iteradores que también son iterables

Los iteradores del lenguaje (los de `entries()`, `keys()`, `values()`…) tienen también un `[Symbol.iterator]` que se devuelve a sí mismo. Por eso puedes recorrerlos con `for...of`, aunque solo una vez:

```js
const it = ["x", "y"].values();

console.log([...it]);  // [ 'x', 'y' ]
console.log([...it]);  // []: ya se consumió
```

## Resumen

- Un **iterable** tiene `[Symbol.iterator]()`, que devuelve un **iterador**.
- Un iterador tiene `next()`, que devuelve `{ value, done }`.
- `for...of`, spread, desestructuración, `Array.from` y `new Map/Set` usan el protocolo.
- Tus objetos son iterables si implementan `[Symbol.iterator]`.
- Un iterable se recorre muchas veces; un iterador, una sola.
