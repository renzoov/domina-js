## Crear un símbolo

Un símbolo se crea llamando a `Symbol()`, **sin `new`**. Puedes darle una descripción, que solo sirve para reconocerlo al depurar:

```js
const id = Symbol("id");

console.log(typeof id);        // symbol
console.log(id.description);   // id
console.log(id.toString());    // Symbol(id)
```

Lo que lo hace especial es que **cada símbolo es único**. Dos símbolos con la misma descripción siguen siendo distintos:

```js
console.log(Symbol("id") === Symbol("id"));  // false
```

## Símbolos como claves de propiedad

El uso principal de un símbolo es servir de **clave** en un objeto. Se escribe entre corchetes:

```js
const visto = Symbol("visto");

const articulo = {
  titulo: "Aprende JS",
  [visto]: true,
};

console.log(articulo[visto]);       // true
console.log(Object.keys(articulo)); // [ 'titulo' ]
console.log(JSON.stringify(articulo)); // {"titulo":"Aprende JS"}
```

Una propiedad con clave símbolo tiene dos ventajas:

- **No choca** con ninguna otra: aunque el objeto tenga otra propiedad llamada `visto`, tu símbolo es otra clave.
- **No aparece** en `Object.keys`, en los bucles `for…in` ni en `JSON.stringify`. El objeto se ve y se guarda igual que antes.

Por eso las librerías los usan para guardar datos propios en objetos que no les pertenecen, sin riesgo de pisar nada.

<Nota>
  Un símbolo no es un mecanismo de seguridad. `Object.getOwnPropertySymbols(objeto)` lista las claves símbolo, y cualquiera que tenga el símbolo puede leer la propiedad. Para datos privados de verdad existen los campos `#privados` de las clases (sección de Clases).
</Nota>

## El registro global: Symbol.for

A veces quieres que distintas partes del programa compartan **el mismo** símbolo. Para eso existe un registro global: `Symbol.for(clave)` busca un símbolo con esa clave y, si no existe, lo crea:

```js
const a = Symbol.for("app.usuario");
const b = Symbol.for("app.usuario");

console.log(a === b);              // true: es el mismo
console.log(Symbol.keyFor(a));     // app.usuario
```

Usa una clave con un prefijo propio, como `"app."`, para no coincidir con el registro de otra librería.

## Los símbolos que usa el propio lenguaje

JavaScript define varios **símbolos conocidos** (*well-known symbols*) que le permiten a tus objetos engancharse a comportamientos del lenguaje. El más famoso es `Symbol.iterator`: si un objeto tiene un método con esa clave, se puede recorrer con `for…of`.

```js
console.log(typeof Symbol.iterator);              // symbol
console.log(typeof "hola"[Symbol.iterator]);      // function: los strings son recorribles
```

Los vas a usar en las secciones de *Iteradores y generadores* y *Metaprogramación*. Por ahora basta con saber que existen y que son símbolos.

## Resumen

- `Symbol("descripción")` crea un **valor único**, sin `new`. Dos símbolos nunca son iguales.
- Sirven como **claves de propiedad** que no chocan con otras y quedan fuera de `Object.keys`, `for…in` y JSON.
- No son seguridad: se pueden listar con `Object.getOwnPropertySymbols`.
- `Symbol.for(clave)` comparte un mismo símbolo en todo el programa.
- El lenguaje usa **símbolos conocidos**, como `Symbol.iterator`, para comportamientos como `for…of`.
