## El contexto de ejecución

Un **contexto de ejecución** es el "espacio de trabajo" donde corre un trozo de código. Contiene:

- Las **variables y funciones** declaradas ahí.
- Una referencia a su **entorno exterior**, para buscar lo que no encuentra dentro. Es la cadena de scopes, el próximo tema.
- El valor de **`this`**, que verás en la sección de Funciones.

Hay un **contexto global**, creado al empezar el programa, y **uno nuevo por cada llamada a función**. Esos contextos son los marcos que viste en la pila de llamadas: cada vez que se llama a una función, su contexto se apila; cuando termina, se desapila.

## Dos fases: creación y ejecución

Cada contexto pasa por dos fases:

1. **Creación**: el motor recorre el código del contexto **sin ejecutarlo** y registra todas las declaraciones.
2. **Ejecución**: recién ahora ejecuta las líneas, una por una.

Lo que se registra en la creación, y cómo, depende del tipo de declaración:

| Declaración | En la fase de creación queda… | Si la usas antes de su línea… |
|---|---|---|
| `var x = 5` | registrada con `undefined` | vale `undefined`, sin error |
| `let x = 5` / `const x = 5` | registrada **sin inicializar** | `ReferenceError` |
| `function f() {}` | registrada **completa**, con su cuerpo | funciona |
| `const f = function () {}` | igual que `const` | `ReferenceError` |

A este comportamiento se le llama **hoisting** ("elevación"), porque es *como si* las declaraciones subieran al principio. Pero nada se mueve: es la fase de creación la que las registra antes de ejecutar.

## La zona muerta temporal

Entre el inicio de su bloque y su propia línea, una variable `let` o `const` existe pero está **en la zona muerta temporal** (TDZ, *temporal dead zone*). Usarla ahí es un error:

```js
try {
  console.log(color);
  let color = "azul";
} catch (error) {
  console.log(error.message);
}
```

Parece un fastidio, pero es una protección: con `var` el mismo código imprimiría `undefined` y el fallo pasaría desapercibido.

## Funciones antes de declararlas

Las **declaraciones de función** quedan completas en la fase de creación, así que puedes llamarlas antes de su línea. Eso permite escribir primero el programa principal y abajo los detalles:

```js
console.log(areaCirculo(2));

function areaCirculo(radio) {
  return Math.PI * radio ** 2;
}
```

Las **expresiones de función** guardadas en una constante no tienen ese privilegio: siguen las reglas de `const`.

```js
try {
  console.log(saludar("Ana"));
} catch (error) {
  console.log(error.message);
}

const saludar = function (nombre) {
  return `Hola, ${nombre}`;
};
```

<Nota>
  Aunque el hoisting de funciones permita llamarlas antes, un orden claro se lee mejor. La costumbre más extendida: **declara arriba, usa abajo**. Con `let` y `const`, el motor te avisa si te equivocas.
</Nota>

## Resumen

- Un **contexto de ejecución** guarda las variables de un trozo de código y su enlace al exterior. Hay uno global y uno por cada llamada a función.
- Cada contexto tiene una fase de **creación**, que registra declaraciones, y una de **ejecución**.
- `var` se registra con `undefined`; `let` y `const` quedan en la **zona muerta temporal** hasta su línea.
- Las **declaraciones de función** se elevan completas; las funciones en constantes, no.
- Declara antes de usar: el código se lee mejor y el motor te protege.
