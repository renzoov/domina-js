## Tres tipos de scope

- **Global**: lo que se declara fuera de toda función y bloque. Se ve desde cualquier parte del programa.
- **De función**: cada función crea el suyo. Sus parámetros y variables solo existen dentro.
- **De bloque**: con `let` y `const`, cada par de llaves `{ }` (un `if`, un `for`, un bloque suelto) crea uno.

```js
const app = "domina-js";          // global

function iniciar() {
  const version = 2;              // scope de iniciar()
  if (version > 1) {
    const mensaje = "moderna";    // scope del bloque if
    console.log(app, version, mensaje);
  }
  // console.log(mensaje);        // ReferenceError: no se ve fuera del if
}

iniciar();
```

## La cadena de scopes

Como muestra el pizarrón, cuando usas un nombre el motor lo busca:

1. En el scope **actual**.
2. Si no está, en el scope que lo **rodea**.
3. Y así, **hacia afuera**, hasta el global.
4. Si tampoco está en el global: `ReferenceError: x is not defined`.

Esa secuencia de scopes anidados es la **cadena de scopes**. La búsqueda va siempre **hacia afuera**: desde dentro de una función se ven las variables de fuera, pero nunca al revés.

## Sombreado

Si un scope interior declara una variable con el mismo nombre que una exterior, la interior **tapa** a la exterior dentro de ese scope. Se llama *shadowing* (sombreado):

```js
const color = "azul";

function pintar() {
  const color = "rojo";   // tapa a la de afuera
  console.log(color);     // rojo
}

pintar();
console.log(color);       // azul: la de afuera no cambió
```

Es legal, pero puede confundir. Si te pasa sin querer, cambia uno de los nombres.

## Scope léxico

El scope de una función se decide por **dónde está escrita** en el código, no por desde dónde se la llama. A eso se le llama **scope léxico** (de "léxico", lo escrito):

```js
const saludo = "Hola desde el global";

function mostrar() {
  console.log(saludo);
}

function otra() {
  const saludo = "Hola desde otra";
  mostrar();  // mostrar() fue escrita en el global: ve el saludo global
}

otra();
```

`mostrar` se llama desde `otra`, pero está escrita en el global, así que busca `saludo` en el global. Esta regla es la base de los **closures**, el siguiente tema.

<Nota tipo="consejo">
  Usa el scope más pequeño posible. Declara cada variable dentro del bloque o la función donde se usa, y evita las globales: cualquier parte del programa podría cambiarlas, y encontrar quién lo hizo es difícil.
</Nota>

## Resumen

- Hay scope **global**, **de función** y **de bloque** (este último, solo para `let` y `const`).
- El motor busca un nombre en el scope actual y **sube** hacia afuera hasta encontrarlo; si no, `ReferenceError`.
- Desde adentro se ve hacia afuera, nunca al revés.
- Una variable interior con el mismo nombre **tapa** a la exterior (sombreado).
- El scope es **léxico**: depende de dónde se escribió la función, no de quién la llama.
