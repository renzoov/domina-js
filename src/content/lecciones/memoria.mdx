## Pila y heap

El motor usa dos zonas de memoria:

- **La pila** (*stack*): los marcos de las llamadas a funciones, con sus valores simples. Es pequeña y rapidísima, y se libera sola cuando cada función termina.
- **El heap** (montículo): los **objetos**, arrays y funciones. Es grande, y es lo que administra el recolector.

Cuando haces `const usuario = { nombre: "Ana" }`, el objeto vive en el heap y la variable guarda una **referencia** a él, como viste en *Valores primitivos y objetos*.

## Alcanzabilidad

El recolector no cuenta referencias una a una: se pregunta si un objeto es **alcanzable**. Parte de unas **raíces** (las variables globales y las de las funciones que se están ejecutando) y sigue todas las referencias, marcando lo que encuentra. Lo que no marcó es inalcanzable: basura que puede liberar. A este método se le llama **marcar y barrer** (*mark-and-sweep*).

Una consecuencia importante: dos objetos que se apuntan entre sí, pero a los que nadie más llega, **sí** se liberan. Lo que importa es si se puede llegar a ellos desde las raíces.

<Nota>
  No puedes decidir cuándo pasa el recolector: lo decide el motor, en el momento que le parece mejor. Tu trabajo no es liberar memoria, sino **no retener** referencias que ya no necesitas.
</Nota>

## Fugas de memoria comunes

Una **fuga** es memoria que tu programa ya no usa pero que sigue alcanzable, así que nunca se libera:

- **Cachés que solo crecen**: un `Map` o un array donde guardas resultados y nunca borras nada.
- **Temporizadores olvidados**: un `setInterval` que nunca se detiene sigue manteniendo vivo todo lo que usa su función.
- **Listeners sin quitar**: un `addEventListener` sobre un elemento que ya sacaste de la página.
- **Closures que recuerdan de más**: una función guardada que recuerda un objeto enorme, aunque solo use un dato.
- **Variables globales** que acumulan datos durante toda la vida de la página.

Para encontrarlas, las DevTools tienen la pestaña **Memory**, que toma "fotos" del heap y te deja compararlas.

## WeakMap y WeakSet

Una `WeakMap` es como un `Map` cuyas **claves no retienen** a los objetos: si nadie más apunta al objeto clave, el recolector puede liberarlo y la entrada desaparece sola. Es perfecta para asociar datos extra a objetos que no controlas:

```js
const vistas = new WeakMap();

let articulo = { titulo: "Closures" };
vistas.set(articulo, 1);
console.log(vistas.get(articulo));  // 1

articulo = null;  // el objeto ya no es alcanzable…
// …y su entrada en la WeakMap puede liberarse junto con él
```

A cambio tiene límites: las claves solo pueden ser **objetos** (o símbolos no registrados, desde ES2023), y no se puede recorrer ni preguntar su tamaño, porque sus entradas pueden desaparecer en cualquier momento. `WeakSet` es lo mismo para conjuntos.

## WeakRef y FinalizationRegistry (ES2021)

ES2021 sumó dos herramientas de bajo nivel:

- **`WeakRef`**: una referencia que **no** mantiene vivo al objeto. Con `ref.deref()` obtienes el objeto, o `undefined` si ya fue liberado.
- **`FinalizationRegistry`**: te deja registrar una función que se ejecutará en algún momento **después** de que un objeto sea liberado.

```js
let grande = { datos: "muchos datos" };
const ref = new WeakRef(grande);

console.log(ref.deref()?.datos);  // muchos datos (mientras siga vivo)
```

<Nota tipo="error">
  Úsalas solo si de verdad las necesitas, por ejemplo en cachés avanzadas. El momento de la recolección es impredecible y cambia entre motores, así que un programa que **depende** de ella para funcionar bien es frágil.
</Nota>

## Resumen

- Los objetos viven en el **heap**; las variables guardan referencias a ellos.
- El recolector libera lo que **no es alcanzable** desde las raíces (*mark-and-sweep*). No controlas cuándo.
- Las **fugas** vienen de referencias que olvidaste soltar: cachés, temporizadores, listeners, globales.
- **`WeakMap`** y **`WeakSet`** no retienen sus claves: ideales para datos extra sobre objetos.
- **`WeakRef`** y **`FinalizationRegistry`** (ES2021) existen, pero son para casos avanzados.
