## Claves, valores y entradas

Tres métodos convierten un objeto en un array que sí puedes recorrer:

```js
const stock = { manzanas: 12, peras: 0, uvas: 30 };

console.log(Object.keys(stock));     // las claves
console.log(Object.values(stock));   // los valores
console.log(Object.entries(stock));  // los pares [clave, valor]
```

Con `entries` y la desestructuración (próximo tema) recorres los dos a la vez:

```js
const stock = { manzanas: 12, peras: 0, uvas: 30 };

for (const [fruta, cantidad] of Object.entries(stock)) {
  if (cantidad === 0) console.log(`Falta ${fruta}`);
}
```

## for...in

`for...in` recorre las **claves** de un objeto, incluidas las **heredadas** de su prototipo, si son enumerables. Con objetos literales no suele haber heredadas, pero por eso hoy se prefiere `Object.keys`, que solo devuelve las propias:

```js
const config = { tema: "oscuro", idioma: "es" };

for (const clave in config) {
  console.log(clave, "=", config[clave]);
}
```

<Nota tipo="error">
  No confundas `for...in` (claves de un objeto) con `for...of` (valores de un iterable). Y no uses `for...in` con arrays: recorre los índices como textos, `"0"`, `"1"`…, y puede incluir propiedades extra.
</Nota>

## El orden de las claves

Las claves se recorren en un orden fijo:

1. Primero, las que parecen **números enteros**, de menor a mayor.
2. Después, las demás, en el **orden en que se crearon**.

```js
const mezcla = { z: 1, 10: "diez", a: 2, 2: "dos" };
console.log(Object.keys(mezcla));
```

Si el orden te importa de verdad, con claves numéricas por ejemplo, considera un `Map`, que respeta siempre el orden de inserción.

## Object.hasOwn (ES2022)

Para saber si una propiedad es **propia** del objeto, sin contar las heredadas, usa `Object.hasOwn`. Reemplaza al viejo `obj.hasOwnProperty("x")`, que fallaba con objetos sin prototipo:

```js
const usuario = { nombre: "Ana" };

console.log("nombre" in usuario);              // true
console.log("toString" in usuario);            // true: heredada
console.log(Object.hasOwn(usuario, "toString")); // false: no es propia
```

## Transformar con fromEntries

`Object.fromEntries` hace lo contrario de `entries`: arma un objeto a partir de pares. Juntos forman el patrón para **transformar** un objeto entero:

```js
const precios = { cafe: 2, te: 1.5, jugo: 3 };

const conIva = Object.fromEntries(
  Object.entries(precios).map(([producto, precio]) => [producto, precio * 1.2])
);

console.log(conIva);
console.log(precios);  // el original no cambió
```

## Resumen

- Un objeto **no es iterable**: recorre `Object.keys`, `Object.values` u `Object.entries`.
- `for...in` recorre claves, incluidas las heredadas enumerables; prefiere `Object.keys`.
- Orden: primero las claves enteras, ascendentes; después las demás, por orden de creación.
- `Object.hasOwn` (ES2022) pregunta por propiedades **propias**; `in` incluye las heredadas.
- `entries` → `map` → `fromEntries` transforma un objeto en otro nuevo.
