## La regla en una frase

Una colección débil **recuerda algo sobre un objeto mientras ese objeto exista**, y lo olvida sola cuando el objeto deja de usarse. No tienes que limpiar nada.

## Caso 1: datos asociados a objetos ajenos

Quieres guardar información extra sobre objetos que no son tuyos (elementos de la página, objetos de una librería) sin agregarles propiedades:

```js
const clics = new WeakMap();

function registrarClic(elemento) {
  clics.set(elemento, (clics.get(elemento) ?? 0) + 1);
  return clics.get(elemento);
}

const boton = { id: "enviar" };  // imagina un botón de la página
registrarClic(boton);
console.log(registrarClic(boton));
```

Si el botón desaparece de la página y nadie más lo referencia, su contador se va con él.

## Caso 2: marcar objetos

Una `WeakSet` responde una sola pregunta: "¿ya vi este objeto?". Es perfecta para evitar procesar algo dos veces o para detectar ciclos al recorrer estructuras:

```js
function contarNodos(nodo, vistos = new WeakSet()) {
  if (vistos.has(nodo)) return 0;  // ya pasamos por aquí: hay un ciclo
  vistos.add(nodo);
  let total = 1;
  for (const hijo of nodo.hijos) total += contarNodos(hijo, vistos);
  return total;
}

const a = { hijos: [] };
const b = { hijos: [a] };
a.hijos.push(b);  // a → b → a: un ciclo

console.log(contarNodos(a));  // 2, sin quedarse en un bucle infinito
```

## Caso 3: cachés por objeto

Como el laboratorio de *Memoria*: guardar un resultado caro calculado a partir de un objeto, sin que la caché impida liberarlo.

## Símbolos como claves (ES2023)

Desde ES2023, una `WeakMap` (y una `WeakSet`) también acepta **símbolos** como claves, siempre que no estén registrados. Un `Symbol("…")` es único y puede dejar de usarse, igual que un objeto. Uno creado con `Symbol.for("…")` vive en un registro global y nunca se libera, así que no sirve:

```js
const datos = new WeakMap();
const sesion = Symbol("sesion");
datos.set(sesion, { usuario: "Ana" });
console.log(datos.get(sesion).usuario);  // "Ana"

try {
  datos.set(Symbol.for("global"), 1);
} catch (error) {
  console.log(error.name);  // "TypeError": un símbolo registrado no se libera nunca
}
```

## Lo que no pueden hacer

| | `Map` / `Set` | `WeakMap` / `WeakSet` |
|---|---|---|
| Claves | Cualquier valor | Solo objetos (y símbolos no registrados) |
| `size` | Sí | No |
| Recorrer (`for...of`, `forEach`, `keys`…) | Sí | No |
| `clear()` | Sí | No |
| Retiene las claves | Sí | No |

Todo lo que falta tiene la misma razón: el contenido puede cambiar **en cualquier momento**, cuando pasa el recolector, así que no hay una lista estable que contar ni recorrer.

<Nota tipo="consejo">
  Para elegir, pregúntate: ¿necesito recorrer la colección o saber cuántos elementos tiene? Si la respuesta es sí, usa `Map` o `Set` y bórralos cuando ya no sirvan. Si solo necesitas consultar por un objeto concreto, la versión débil te ahorra esa limpieza.
</Nota>

## Resumen

- Las colecciones débiles recuerdan datos **mientras el objeto exista**.
- `WeakMap`: datos extra sobre objetos ajenos y cachés por objeto.
- `WeakSet`: marcar objetos ya vistos o procesados, y detectar ciclos.
- No tienen `size`, no se recorren y solo aceptan objetos como claves, o símbolos no registrados desde ES2023.
- ¿Hay que recorrer? `Map`/`Set`. ¿Solo consultar por objeto? La versión débil.
