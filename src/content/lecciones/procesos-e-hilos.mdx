## Ejecutar otros programas

```js
import { execFile, spawn } from "node:child_process";
import { promisify } from "node:util";

// Un comando corto: esperar el resultado completo
const execFileP = promisify(execFile);
const { stdout } = await execFileP("git", ["log", "-1", "--format=%s"]);
console.log("último commit:", stdout.trim());

// Un proceso largo o con mucha salida: ir leyendo a medida que llega
const conversion = spawn("ffmpeg", ["-i", "video.mp4", "audio.mp3"]);
conversion.stderr.on("data", (parte) => process.stdout.write("."));
conversion.on("error", (e) => console.error("no se pudo ejecutar ffmpeg:", e.message));
conversion.on("close", (codigo) => console.log(codigo === 0 ? "\nlisto" : `\nfalló (${codigo})`));
```

- **`execFile`**: ejecuta un programa con argumentos en un array y devuelve toda la salida.
- **`spawn`**: igual, pero con streams para la entrada y la salida, para procesos largos.
- **`exec`**: ejecuta un **texto** a través de una terminal (`sh` o `cmd`). Cómodo, pero peligroso.

<Nota tipo="error">
  Nunca armes un comando de `exec` con datos de afuera: `exec("convert " + nombre)` con un nombre como `"foto.jpg; rm -rf ~"` ejecuta ese segundo comando. Es una **inyección de comandos**. Con `execFile` o `spawn`, cada argumento va separado y no pasa por una terminal.
</Nota>

## worker_threads

Para cálculos pesados en JavaScript, un **worker thread** corre en otro hilo del mismo proceso, como los Web Workers del navegador:

```js
// hash.mjs
import { parentPort, workerData } from "node:worker_threads";
import { scryptSync } from "node:crypto";

const resultado = scryptSync(workerData.clave, "sal", 64).toString("hex");
parentPort.postMessage(resultado);
```

```js
// servidor.mjs
import { Worker } from "node:worker_threads";

function hashEnOtroHilo(clave) {
  return new Promise((resolver, rechazar) => {
    const w = new Worker(new URL("./hash.mjs", import.meta.url), { workerData: { clave } });
    w.once("message", resolver);
    w.once("error", rechazar);
  });
}

console.log(await hashEnOtroHilo("secreto"));
```

Crear un worker cuesta: para muchas tareas, se usa un **pool** de workers reutilizables (por ejemplo, con la librería Piscina). Y para tareas que Node.js ya hace fuera del hilo (leer archivos, la mayoría de la criptografía asíncrona), no hacen falta: usa sus versiones asíncronas.

## El proceso actual

`process` tiene información y control sobre el programa que está corriendo:

```js
console.log(process.argv);        // [ruta de node, ruta del script, ...argumentos]
console.log(process.env.HOME);    // variables de entorno
console.log(process.pid, process.platform, process.version);
console.log(process.memoryUsage().heapUsed);

// Terminar con orden cuando piden detener el programa (Ctrl+C, o el sistema)
process.on("SIGINT", async () => {
  console.log("cerrando conexiones…");
  await cerrarTodo();
  process.exit(0);   // 0: todo bien; otro número: hubo un error
});
```

El **código de salida** importa: los scripts, las herramientas de integración continua y los contenedores lo usan para saber si el programa terminó bien. `process.exitCode = 1` lo fija sin cortar el programa en seco.

## Resumen

- `execFile` y `spawn` ejecutan otros programas con argumentos separados; `exec` pasa por una terminal: cuidado con la inyección.
- Escucha siempre el evento `error` de un proceso hijo.
- `worker_threads` ejecuta JavaScript pesado en otro hilo, comunicándose por mensajes.
- `process` da los argumentos, las variables de entorno, las señales y el código de salida.
